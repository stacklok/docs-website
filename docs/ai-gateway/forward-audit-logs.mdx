The AI Gateway emits structured JSON audit events to pod standard output. It
writes one event for each model interaction, one for each rejected
authentication attempt, and one for each model list request that model access
filters down to nothing.

Events record decisions and metadata only. They never carry prompts,
completions, credentials, request or response bodies, token claims, or email
addresses.

Every event carries the fields required by NIST SP 800-53 controls AU-2, AU-3,
and AU-8: a unique audit ID, a UTC timestamp, the outcome, the component, the
source, an optional target, and an extra block for forensic correlation. Events
for authenticated requests also carry the subject.

For the legacy AI Gateway, see
[legacy gateway audit logs](./legacy/forward-audit-logs.mdx).

## Enable audit events

Audit events are off by default. Turn them on for the gateway:

```yaml title="values.yaml"
ai-gateway-v2:
  audit:
    enabled: true
```

Setting `global.stacklok.audit.enabled: true` also turns them on, and while it's
`true`, `audit.enabled: false` has no effect. The change applies when the
gateway pods roll out; see
[How configuration changes apply](../platform/enterprise-platform/configure-ai-gateway.mdx#how-configuration-changes-apply).

Enabled audit events cover every interaction without sampling, and there are no
per-event toggles. Filter and route events in your log pipeline.

## What gets captured

| Event type                      | Fires when                                                                                              | Outcome                            |
| ------------------------------- | ------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| `aigw.v2.interaction.completed` | An authenticated generation request reaches its final outcome, including an early refusal               | success, denied, failure, or error |
| `aigw.v2.authentication.failed` | The gateway rejects a credential on a protected route, or can't reach a service it needs to validate it | failure, or error when unreachable |
| `aigw.v2.models.no_grant`       | Model access filters a non-empty model list to nothing, and the caller receives a `200`                 | denied                             |

Interaction events cover the OpenAI Chat Completions, OpenAI Responses,
Anthropic Messages, and Gemini generate and stream-generate endpoints. A
streaming interaction emits one event when it finishes, never one per frame.
Health endpoints emit no events, and a model list request that returns at least
one model emits none.

## Event schema

```json
{
  "time": "2026-10-16T14:22:31Z",
  "level": "INFO",
  "msg": "audit_event",
  "logger": "audit",
  "audit_id": "b3d4f7a2-8c11-4f6e-9b0a-1c2d3e4f5a6b",
  "type": "aigw.v2.interaction.completed",
  "logged_at": "2026-10-16T14:22:31.418Z",
  "outcome": "success",
  "component": "v2",
  "source": { "type": "local", "value": "ai-gateway-v2-6d8f9c7b5-x2k4q" },
  "subjects": { "user": "00u1a2b3c4d5e6f7g8h9", "department": "engineering" },
  "target": {
    "model": "claude-sonnet-4-6",
    "provider": "anthropic",
    "route": "/v1/messages"
  },
  "metadata": {
    "extra": {
      "schema_version": 1,
      "request_id": "c0ffee01-2a3b-4c5d-6e7f-8091a2b3c4d5",
      "interaction_id": "7e1d5390-41e5-4f71-b3c2-9a0815793c4a",
      "trace_id": "4bf92f3577b34da6a3ce929d0e0e4736",
      "span_id": "00f067aa0ba902b7",
      "http_method": "POST",
      "http_status": 200,
      "dialect": "anthropic-messages",
      "streaming": true,
      "duration_ms": 8421,
      "terminal_stage": "delivery",
      "reason_code": "delivered",
      "usage_present": true,
      "input_tokens": 1834,
      "output_tokens": 412
    }
  }
}
```

**Subjects** appear only after authentication succeeds. `user` is the caller's
canonical subject, and `virtual_key_id` identifies the virtual key on
virtual-key requests. Directory group labels named in `directory.groupLabels`,
such as `department`, are added alongside them. A rejected authentication event
carries no subjects, except an `auth_identity_unresolved` refusal, which names
the verified caller in `user`.

A [service account](../platform/enterprise-directory/service-accounts.mdx)'s
events name its workload instead of a user. `service_account` is the verified
subject, in the form `system:serviceaccount:<NAMESPACE>:<NAME>`,
`service_account_authority` identifies the trusted issuer that verified it, and
`service_account_uid` is the ServiceAccount's UID, which tells a recreated
ServiceAccount apart from the one it replaced.

**Targets** carry `model`, `provider`, and `route`, each only once the gateway
has resolved it. `provider` is the provider `kind` from the gateway
configuration: `openai`, `openrouter`, `anthropic`, `bedrock-anthropic`,
`gemini-aistudio`, or `vertex`. `route` is the endpoint path template.

**Source** is the gateway pod that wrote the event. Events carry no client IP
address or user agent.

**Common extras** are `schema_version`, `request_id`, `http_status`, and, when
tracing is on, `trace_id` and `span_id` for OpenTelemetry correlation. The
gateway also returns `request_id` to the client in the `X-Request-ID` response
header. Authentication events add `auth_method`: `jwt`, `virtual_key`,
`workload`, or `unknown`, and `reason_code`, which says why authentication
failed, such as `auth_identity_unresolved`.

Interaction events add `interaction_id`, `http_method`, `dialect`, `streaming`,
`duration_ms`, `terminal_stage`, `reason_code`, and `usage_present`, plus
`input_tokens` and `output_tokens` when the provider reported usage.
`terminal_stage` is the stage the interaction ended in: `validation`, `routing`,
`governance`, `provider`, `metering`, or `delivery`. `reason_code` says what
ended it, such as `delivered` or `governance_denied`. When a governance hook
denies or fails a request, `hook` names the hook entry.

Required governance hooks can report annotations under `hook_annotations`, keyed
by hook entry name. The budgets entries report the charged subject and amount,
and the `scanning` entry reports the entity types it acted on, such as
`detection_types` for a block and `redact_types` for a redaction.

## Related logs

The **Kubernetes API audit log** covers control-plane activity such as `kubectl`
calls and Helm upgrades. Configure it through the API server audit policy.

**Operational failure records** go to the gateway's standard error, separate
from audit events. A record can name the caller by directory email and, by
default, includes a bounded parsed error message to make failures easier to
diagnose. `failureLogs.level` sets their severity: `warn` (the default),
`error`, or `debug`. When log retention or access can't accommodate personal
data, set `failureLogs.includeMessage` to `false` to drop the message.

**Conversation content** reaches no audit event. Screening sends prompt text to
Presidio and AWS Bedrock for analysis. Snapshot capture, configured with the
top-level `capture` value, records full request and response bodies for testing.
It's unset by default; leave it unset in production.
