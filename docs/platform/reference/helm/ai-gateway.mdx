### `telemetry`

**Type:** `object`

<details>
<summary>Default value</summary>

```yaml
headerLabels: []
metrics:
  port: 9464
otlp:
  enabled: false
  endpoint: ''
  insecure: false
prometheus:
  enabled: false
tracing:
  enabled: false
  samplingRate: 0
```

</details>

Metrics and tracing export (opt-in). Both metrics exporters and tracing default
off — no OTLP push, no Prometheus pull, no /metrics route, no spans anywhere.
Field names mirror cmd/sprout/main.go's
telemetryConfig/otlpConfig/prometheusConfig/tracingConfig exactly
(Enabled/Insecure/Endpoint on otlp; Enabled on prometheus; Enabled/ SamplingRate
on tracing) — sprout's strict decoder rejects any field these structs don't
declare, so this chart must never invent one. `otlp` composes with
global.stacklok.telemetry.otlp (#4409) field by field: `endpoint` coalesces
(this chart's own value wins when set, else the global endpoint is used);
`enabled`/`insecure` are ADDITIVE with their global counterpart (true if either
is true) — there is no local setting that forces either off while the global
default is on. `tracing` has no global counterpart of its own; it shares
whichever otlp.endpoint (local-or-global) that composition resolves.

### `readinessProbe`

**Type:** `object`

<details>
<summary>Default value</summary>

```yaml
failureThreshold: 2
httpGet:
  path: /readyz
  port: http
initialDelaySeconds: 0
periodSeconds: 5
successThreshold: 1
timeoutSeconds: 3
```

</details>

Readiness probe. Hits /readyz, which answers 200 while serving and
&#123;"status":"not_ready","reason":"draining"&#125; once a graceful drain has
started.

### `livenessProbe`

**Type:** `object`

<details>
<summary>Default value</summary>

```yaml
failureThreshold: 32
httpGet:
  path: /healthz
  port: http
initialDelaySeconds: 0
periodSeconds: 30
successThreshold: 1
timeoutSeconds: 5
```

</details>

Liveness probe. Hits /healthz, a static 200 that never rolls up a dependency.
Its failureThreshold/periodSeconds are sized against the pod-grace inequality:
`(failureThreshold - 1) * periodSeconds > drain-deadline + completion-webhook budget`
At the shipped lifecycle.maxStreamDuration (15m) ceiling, drain-deadline is 900s
and the completion-webhook budget is 5s, so the right-hand side is 905s.
`(32 - 1) * 30 = 930s > 905s` satisfies it. templates/\_helpers.tpl's
sprout.validateLivenessBound guard recomputes this from whatever
lifecycle.maxStreamDuration and livenessProbe values an operator sets, and fails
the render naming both sides if the inequality breaks.

### `runtime`

**Type:** `object`

**Default:** `{"drainDeadline":"","drainWindow":"","jwksWarmupTimeout":""}`

Process flags cmd/sprout reads at startup, which are NOT config-file fields (the

### `runtime.drainWindow`

**Type:** `string`

**Default:** `""`

`-drain-window`: how long a draining pod keeps ACCEPTING connections after
SIGTERM, buying time for its EndpointSlice removal to propagate through
kube-proxy/CNI. Go duration string. Binary default 5s.

### `runtime.drainDeadline`

**Type:** `string`

**Default:** `""`

`-drain-deadline`: overrides the deadline otherwise DERIVED from
lifecycle.maxStreamDuration (drainDeadlineFor in cmd/sprout/main.go). Leave
empty to keep the derived value, which is what the rendered
terminationGracePeriodSeconds is sized against — setting this without also
raising lifecycle.maxStreamDuration decouples the two. Go duration string.

### `runtime.jwksWarmupTimeout`

**Type:** `string`

**Default:** `""`

`-jwks-warmup-timeout`: per-issuer budget for the blocking first JWKS fetch at
startup. An issuer that misses it is fatal (the process exits rather than
serving 401s with a valid token). Go duration string. Binary default 10s.

### `lifecycle.maxStreamDuration`

**Type:** `string`

**Default:** `"15m"`

The upstream stream ceiling every other timing in this chart derives from: the
derived terminationGracePeriodSeconds, the liveness-bound guard above, the
ConfigMap's lifecycle.max_stream_duration (which the binary's own
validateDrainBudgetFitsGrace re-checks at startup), and httpRoute.timeouts
below. Go duration string.

### `providers`

**Type:** `list`

**Default:** `[]`

Upstream providers. Each entry mirrors catalog.ProviderConfig
(enterprise/sprout/catalog/catalog.go): kind, baseUrl, models, and the per-kind
fields a kind actually reads (region for bedrock-anthropic/vertex; project for
vertex; awsProfile for bedrock-anthropic). credentialSecretRef names the
Secret+key backing that provider's credential; the chart mounts it and writes
the matching _\_file field (api_key_file / aws_credentials_file /
gcp_service_account_file) — never an inline plaintext credential, which
templates/\_helpers.tpl's sprout.validateConfig REFUSES outright (the ConfigMap
is plaintext; only the _\_file indirection keeps the credential bytes in a
Secret). A provider naming no credentialSecretRef renders no mount and no
\*\_file key — the shipped Bedrock ambient-credential-chain posture (EKS Pod
Identity) keeps working.

```yaml
Example:
  providers:
    - kind: openai
      baseUrl: https://api.openai.com
      models: ['gpt-5.5']
      credentialSecretRef:
        name: ai-gateway-v2-openai-credentials
        key: api-key
    - kind: bedrock-anthropic
      baseUrl: https://bedrock-runtime.us-east-1.amazonaws.com
      region: us-east-1
      models: ['us.anthropic.claude-opus-4-8']
      # No credentialSecretRef: resolves the AWS default credential chain
      # (EKS Pod Identity) at runtime.
```

### `networkPolicy.ingress.gatewayNamespaces`

**Type:** `list`

**Default:** `["envoy-gateway-system"]`

Namespaces whose pods may reach the gateway port. The shared Envoy Gateway's
data plane is the only thing that should: sprout sits behind it and has no

**Type:** `object`

**Default:** `{"app.kubernetes.io/name":"envoy"}`

Optional narrowing WITHIN those namespaces. The default names the Envoy pods

whole namespace.

### `networkPolicy.ingress.monitoringNamespaces`

**Type:** `list`

**Default:** `["monitoring"]`

Namespaces whose pods may scrape the dedicated /metrics listener, applied only
when telemetry.prometheus.enabled is true. Scoped to the metrics port alone, so
admitting a monitoring namespace never becomes a second way into the gateway's
ingress listener. The listener is UNAUTHENTICATED, so this list is the only
thing bounding who reads it.

### `networkPolicy.ingress.allowAllSources`

**Type:** `bool`

**Default:** `false`

Admit every source instead of the lists above. An explicit, auditable opt-out
for an install whose namespace topology the defaults do not fit; it is not a
default, because an allow-all ingress rule leaves the unauthenticated /metrics
listener readable by every pod in the cluster.

### `networkPolicy.governanceEgress`

**Type:** `object`

**Default:**
`{"enabled":true,"namespaces":[],"podSelector":{"app.kubernetes.io/name":"enterprise-manager"}}`

When allowExternalEgress is false, emit egress rules to the governance services
this install actually dials (directory, budgets, and the enterprise-manager the
Gateway connectivity poll reads), with the ports taken from directory.endpoint
and budgets.endpoint, and enterprise-manager admitted by its named `http`
container port, so a port change cannot orphan the rule. Without them a
locked-down install fails CLOSED at request time — budget admission is
fail-closed, so every request 503s — with nothing in the Helm or pod state to
point at.

### `networkPolicy.governanceEgress.namespaces`

**Type:** `list`

**Default:** `[]`

Namespaces the governance services run in. Empty means the release namespace,
which is where the umbrella installs enterprise-manager. If directory.endpoint
or budgets.endpoint instead point at a service in a DIFFERENT namespace, this
must be set to match, or the emitted egress rule scopes to the wrong namespace
and admits nothing — the same silent fail-closed 503 as a port mismatch, since
NetworkPolicy has no visibility into what a hostname resolves to, only which
namespace/pod selector it's scoped to.

### `networkPolicy.governanceEgress.podSelector`

**Type:** `object`

**Default:** `{"app.kubernetes.io/name":"enterprise-manager"}`

Pods within those namespaces. Set to &#123;&#125; to admit the whole namespace.

**Type:** `bool`

### `scanning.resultCache.macSecret.name`

**Type:** `string`

**Default:** `""`

Bring your own Secret holding the cache's HMAC key, in the release namespace
(e.g. one managed by External Secrets or sealed-secrets). The adapter then only
reads it and creates nothing, which is what makes the arrangement safe: a second
writer at the same name would race the manager that owns it and replace the
value, cold-starting the cache.

Empty makes the adapter provision one itself, named `<fullname>-ner-cache-mac`:
at startup it gets the Secret and creates it when absent, and replicas that race
on the create converge on one key. Provisioning is create-if-absent on every
start, so it works on a fresh install and an upgrade alike, and a restart never
replaces a live value. The value is 48 bytes of crypto/rand, base64-encoded so
it is safe to carry as an env var, and it never passes through Helm values. The
chart renders a Role and RoleBinding granting the adapter get (pinned to that
Secret) and create in the release namespace; without that grant the adapter logs
a WARN and runs uncached. The Secret is not owned by the release, so it survives
uninstall and a Helm or Argo prune.

A supplied Secret's value must be at least 32 bytes of printable text, not raw
bytes: it reaches the pod as an env var, and the kubelet cannot ship a non-UTF-8
env value over CRI (the pod sticks in CreateContainerError). A missing Secret
leaves the cache off.

Rotation, either way, is to replace the Secret's value and restart the adapter.
Every existing entry then fails verification and is re-scanned: a cache cold
start, never a correctness event, and the whole incident response for a leaked
secret.
