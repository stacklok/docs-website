**Type:** `string`

### `internalApi.audience`

**Type:** `string`

The aud claim a caller's token must carry. Must equal the enterprise-manager

### `internalApi.allowedSubjects`

**Type:** `list`

**Default:** `[]`

ServiceAccount subjects (`system:serviceaccount:<namespace>:<name>`) permitted
to call; required when enabled. Each can revoke any User's stored upstream
tokens on this gateway. A set list replaces the derived one, so include
enterprise-manager's subject yourself.

### `internalApi.deriveEnterpriseManagerSubject`

**Type:** `bool`

**Default:** `false`

When allowedSubjects is empty, derive the same-release enterprise-manager's
subject. The umbrella sets this; leave false standalone so an empty list is
refused.

### `internalApi.issuer`

**Default:** `""`

### `vmcpConfig`

**Type:** `object`

<details>

### `vmcpConfig.outgoingAuth`

**Type:** `object`

**Default:** `{"source":"discovered"}`

### `enterpriseConfig`

**Type:** `string`

**Default:** `nil`

Enterprise-only configuration (authServer, directory, outbox, metering, redis,
...), strict-decoded by the gateway. `gateway.id` and `authServer.issuer` are
chart-owned (from global.stacklok.connectorGatewayId and
global.stacklok.authServerIssuer); setting either here is refused at render.

### `appConfig`

**Type:** `object`

**Default:** `{}`

Inline AppConfig override, deep-merged over the chart-computed document; keys
here win. Set `logLevel: debug` to raise log verbosity. `primaryIdp` overrides
global.stacklok.primaryIdp per install; its `clientClaim` is limited to
cid/client_id/azp/appid unless `clientClaimAllowUnsafe: true`. For an Entra v2.0
issuer the chart renders clientClaim azp and subjectClaim oid (scopes must
include profile) and refuses other values.

```yaml

  featureFlags:
    aiGateway: true
  # primaryIdp:
  #   clientClaim: azp
```

### `directoryTLS`

**Type:** `object`

<details>
<summary>Default value</summary>

```yaml
audience: directory-service
caBundle:
  key: ca.crt
  secretName: ''
enabled: false
expirationSeconds: 3600
mountPath: /etc/directory-tls
tokenMountPath: /var/run/secrets/directory
```

</details>

Chart-managed transport to Directory's gRPC API: mounts the CA bundle, projects
an audience-bound ServiceAccount token, and writes the matching
enterpriseConfig.directory.tls paths. When enabled, a hand-written directory.tls
is refused. A rotated CA bundle takes effect only after a pod restart; the token
refreshes in place.

### `directoryTLS.enabled`

**Type:** `bool`

**Default:** `false`

Enable the chart-managed directory transport: the CA bundle mount, the projected
ServiceAccount token, and the app-config paths that name them.

### `directoryTLS.caBundle.secretName`

**Type:** `string`

**Default:** `""`

Secret holding the PEM bundle that verifies Directory's serving certificate.
Required when enabled. Use a CA-only Secret, not cert-manager's
&#60;fullname&#62;-grpc-tls, which also holds the serving private key.

### `directoryTLS.caBundle.key`

**Type:** `string`

**Default:** `"ca.crt"`

Key within that Secret holding the PEM bundle; also names the mounted file. Must
be non-empty and not tls.key.

### `directoryTLS.mountPath`

**Type:** `string`

**Default:** `"/etc/directory-tls"`

Directory the CA bundle Secret is mounted into.

### `directoryTLS.tokenMountPath`

**Type:** `string`

**Default:** `"/var/run/secrets/directory"`

Directory the projected ServiceAccount token is mounted into (as `token`).

### `directoryTLS.audience`

**Type:** `string`

**Default:** `"directory-service"`

Audience Directory's caller-auth gate expects. Fixed on the Directory side, so
changing it breaks every call. Must be non-empty.

### `directoryTLS.expirationSeconds`

**Type:** `int`

**Default:** `3600`

Requested projected-token lifetime. Minimum 600: the API server rejects the Pod
below that.

### `kek`

**Type:** `object`

<details>
<summary>Default value</summary>

```yaml
activeVersion: ''
allowGenerateOnUpgrade: false
existingSecret: ''
generate: false
keyringGeneration: ''
value: ''
```

</details>

KEK for embedded auth-server envelope encryption. Required when the effective
AppConfig enables `authServer`. Choose exactly one source below; losing or
replacing the key makes existing credentials unreadable. See
[Rotate the encryption key](https://docs.stacklok.com/connector-gateway/rotate-encryption-key).

### `kek.existingSecret`

**Type:** `string`

**Default:** `""`

Existing Secret in the release namespace with key material under `kek`. The
chart does not manage it. Required for Argo CD and render-and-apply workflows.
Restart pods after changing its content; retain old versions during rotation.

### `kek.value`

**Type:** `string`

**Default:** `""`

Inline, base64-encoded key material. Accepted decoded forms:

single key base64 of 32 random bytes `openssl rand -base64 32` version map
base64 of &#123;"1":"&#60;base64 32B&#62;","2":"&#60;base64 32B&#62;"&#125;

Rotation requires the version map. Prefer `existingSecret`; Helm release data
and `helm get values` expose inline values.

### `kek.generate`

**Type:** `bool`

**Default:** `false`

Generate and preserve a version-1 key on a live Helm install. Do not use with
`helm template`, Argo CD, or other render-and-apply workflows because they
cannot preserve a key through `lookup`.

### `kek.allowGenerateOnUpgrade`

**Type:** `bool`

**Default:** `false`

Allow generation during an upgrade only for a confirmed first enable. A lookup
miss can also mean missing Secret RBAC or a client-only renderer.

### `kek.activeVersion`

**Type:** `string`

**Default:** `""`

Keyring version new writes seal under; empty means the highest present. Pin it
during a two-phase rotation so no replica writes under a key a peer cannot yet
read.

### `kek.keyringGeneration`

**Type:** `string`

**Default:** `""`

Free-form token hashed into the pod checksum to force a rollout. Required in
existingSecret and generate modes, where Secret content changes are invisible to
the chart: bump it on every rotation phase one.

### `authServerKeys`

**Type:** `object`

<details>
<summary>Default value</summary>

```yaml
allowGenerateOnUpgrade: false
existingSecret: ''
generate: false
rotatedHmacSecretKeys: []
rotatedSigningKeys: []
```

</details>

Durable key material for the embedded auth server. Required when the effective
AppConfig enables `authServer`. Choose exactly one source below.

### `authServerKeys.existingSecret`

**Type:** `string`

**Default:** `""`

Existing Secret in the release namespace containing `signing-key.pem` (PEM ECDSA
private key) and `hmac-secret` (at least 32 bytes, e.g.
`openssl rand 32 > hmac-secret`). The chart does not manage it. Required for
Argo CD and render-and-apply workflows.

### `authServerKeys.generate`

**Type:** `bool`

**Default:** `false`

Generate and preserve an ECDSA P-256 signing key and a separate 32-byte HMAC
secret on a live Helm install. Do not use with `helm template`, Argo CD, or
other render-and-apply workflows because they cannot preserve generated material
through `lookup`.

### `authServerKeys.allowGenerateOnUpgrade`

**Type:** `bool`

**Default:** `false`

Allow generation during an upgrade only for a confirmed first enable. A lookup
miss can also mean missing Secret RBAC or a client-only renderer.

### `authServerKeys.rotatedHmacSecretKeys`

**Type:** `list`

**Default:** `[]`

Keys in the existingSecret Secret holding retired HMAC secrets, still accepted
for outstanding authorization codes and refresh tokens. Requires existingSecret.

### `authServerKeys.rotatedSigningKeys`

**Type:** `list`

**Default:** `[]`

Keys in the existingSecret Secret holding retired signing keys, still published
in the JWKS. Requires existingSecret. Remove each once its tokens expire: a
listed compromised key keeps forged tokens valid.

### `networkPolicy.enabled`

**Type:** `bool`

**Default:** `false`

Enable a NetworkPolicy for the connector-gateway pod.

### `networkPolicy.allowExternalEgress`

**Type:** `bool`

**Default:** `true`

Allow ALL egress. NetworkPolicies are additive, so true overrides any cluster
default-deny egress. Set false and populate `egress` to lock down this pod,
which holds the KEK and the primary-IdP client secret.

### `networkPolicy.egress`

**Type:** `list`

**Default:** `[]`

Egress rules (NetworkPolicyEgressRule shape) applied when allowExternalEgress is
false. Must cover DNS and every IdP, Directory, backend, Redis and metering
destination, plus the kube-apiserver when internalApi.enabled. A missing rule
fails silently.
