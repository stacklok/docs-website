## Values

### `replicaCount`

**Type:** `int`

**Default:** `1`

Number of replicas for the deployment. Ignored when ha.enabled or
autoscaling.enabled is true.

### `ha`

**Type:** `object`

<details>
<summary>Default value</summary>

```yaml
antiAffinityPreset: soft
enabled: false
podDisruptionBudget:
  minAvailable: 1
replicaCount: 2
```

</details>

High availability. Bundles replica count, a PodDisruptionBudget, and pod
anti-affinity together so they can't drift apart — specifically, so a PDB can
never be enabled without enough replicas to back it. A PDB with minAvailable
&#62;= the actual replica count blocks every voluntary disruption forever (node
drains, cluster upgrades, cluster-autoscaler scale-down all wait on a budget
Kubernetes can never satisfy while evicting a pod). The chart refuses to render
if ha.enabled is true with fewer than 2 replicas.

### `ha.enabled`

**Type:** `bool`

**Default:** `false`

Enable HA mode: replicaCount above is ignored in favor of ha.replicaCount, a
PodDisruptionBudget is created, and pod anti-affinity spreads replicas across
nodes and zones.

### `ha.replicaCount`

**Type:** `int`

**Default:** `2`

Replica count used when ha.enabled is true.

### `ha.podDisruptionBudget.minAvailable`

**Type:** `int`

**Default:** `1`

Minimum number of pods that must remain available.

### `ha.antiAffinityPreset`

**Type:** `string`

**Default:** `"soft"`

Pod anti-affinity preset spreading replicas across nodes: "soft" (preferred —
schedules even if it can't spread) or "hard" (required — refuses to schedule a
replica on a node that already has one). Spreading across zones is always
preferred, never required, so a single-zone cluster still schedules every
replica.

### `networkPolicy`

**Type:** `object`

**Default:** `{"allowExternalEgress":true,"egress":[],"enabled":false}`

NetworkPolicy. Off by default. Turning this on matters most for clusters running
a default-deny policy engine (Kyverno's add-network-policy, OPA Gatekeeper):
those engines auto-attach a deny-all NetworkPolicy to any pod that has none of
its own, so a chart that ships zero NetworkPolicy silently loses whatever
traffic that engine decides to block. Shipping our own explicit policy — even a
permissive one — means the cluster no longer treats this pod as unmanaged.

### `networkPolicy.allowExternalEgress`

**Type:** `bool`

**Default:** `true`

Allow all egress traffic. Recommended default: every outbound destination this
app calls is a customer-configured URL (apiBaseUrl,
global.stacklok.primaryIdp.issuer, enterpriseManagerUrl, gatewayApiUrl, redisUrl
/ redisUrlExistingSecret) that can point in-cluster or external — this chart has
no way to know your actual values at template time, so a fixed allow-list here
would be a guess. Set to false to lock egress down to exactly your deployment's
destinations via the egress list below.

### `networkPolicy.egress`

**Type:** `list`

**Default:** `[]`

Additional egress rules (Kubernetes NetworkPolicyEgressRule shape), applied when
allowExternalEgress is false. Must cover DNS (UDP/TCP 53) plus every destination
you've actually configured above — omitting one doesn't fail loudly, the app
just can't reach it.

### `oidc`

**Type:** `object`

**Default:** `{"additionalProviders":[]}`

OIDC / OAuth configuration. The primary provider (issuer/client ID/client
secret/scopes) is no longer configured here — per
docs/design/platform-identity.md, it comes from global.stacklok.primaryIdp, the
single source of truth shared with connector-gateway's default embedded-AS
upstream and enterprise-manager's issuer trust. The old
issuerUrl/clientId/clientSecret/existingSecret/ existingSecretKey/scopes fields
were removed with no compat shim — setting any of them fails the render
(toolhive-cloud-ui.rejectLegacyOidc).

A primary IdP served by a PRIVATE CA additionally needs
global.stacklok.primaryIdp.caBundleRef — exactly one of `secretRef: {name}` or
`configMapRef: {name}`, plus `key` (default ca.crt) — per
docs/design/platform-identity.md. This chart projects that key into the pod and
sets NODE_EXTRA_CA_CERTS to it, which is ADDITIVE to Node's default roots, so
server-side OIDC discovery (fetch(OIDC_DISCOVERY_URL)) trusts that IdP without
this pod losing its trust in public CAs. Read at process start: rotating the
source's CONTENTS in place needs a manual pod roll (changing the ref name or key
changes the pod spec and rolls it automatically).
global.stacklok.primaryIdp.allowPrivateIps is deliberately NOT read here —
Node's fetch does not gate private addresses, so there is nothing to relax.

### `connectorGatewayUrl`

**Type:** `string`

**Default:** `""`

Base URL of the per-user Connector Gateway control-plane API (the
`/v1/users/me/gateway/...` endpoints the "Connectors" pages call). When set,
takes effect via the CONNECTOR_GATEWAY_API_URL env var; the nav entry +
`/tools/connectors*`/`/neo/setup*` routes are hidden while it is unset. Setting
this alone is no longer sufficient to turn the feature on: those surfaces also
require the connector-gateway install toggle
(global.stacklok.connectorGateway.enabled at Helm render time, mirrored into the
mounted AppConfig) to resolve true.

Address the CONTROL-PLANE Service, not the data-plane one: connector-gateway
serves this API on its own port behind `<fullname>-control-plane`
(controlPlane.port, default 8090) — e.g.
http://&#60;release&#62;-connector-gateway-control-plane.&#60;namespace&#62;:8090.
The data-plane Service (`<fullname>`, port 8443) serves /gw/mcp and will not
answer these routes.

Unlike its sibling URL values above, this one is `tpl`-EVALUATED before it
reaches the env var (deployment.yaml). That is what lets the umbrella chart hand
this subchart a template string deriving the address from
`global.stacklok.connectorGateway.enabled` — the component's own install toggle
— rather than requiring an operator to set the same fact twice and get it
silently wrong in either direction. A literal URL has no template actions and
passes through unchanged, so nothing about setting this by hand changes.

Standalone default stays empty: with no umbrella above it, no safe cross-chart
default exists (Service name/namespace and control-plane port are
deployment-specific), and an empty value keeps the feature hidden rather than
pointing the UI at a Service that may not exist.

### `redisUrl`

**Type:** `optional`

**Default:** `""`

(optional) Redis connection URL for server-side caching (currently used to cache
SKILL.md previews pulled from OCI artifacts). External Redis only — the chart
does not deploy a Redis instance. The SKILL.md preview is Redis-gated: when
unset (or when Redis is unreachable) the cloud-ui hides the preview entirely
rather than re-pulling on every request. Example:
"redis://:password@redis.example.com:6379/0"

The URL embeds the Redis password. Prefer redisUrlExistingSecret below, which
keeps the whole connection string (and its embedded credential) out of the
rendered pod spec / Helm release object; redisUrl is kept for backward
compatibility with existing installs that already set it directly.
