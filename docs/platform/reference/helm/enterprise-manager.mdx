### `enterpriseConfig`

**Type:** `object`

**Default:** `{}`

Organization-wide configuration distributed by Enterprise Manager to clients.
Set directives directly under `enterpriseConfig`, as in the commented example in
the chart's default values (`helm show values`). The chart serializes the object
as JSON in a mounted ConfigMap. Use either `enterpriseConfig` or `configFile`.
An empty object creates no enterprise configuration ConfigMap.

Each directive has a typed `value` and a required `enforcement` field:
`enforced` makes the value mandatory; `default` lets clients use their local
settings instead. Omitted directives leave client settings unchanged. The
`degraded_mode` block has no `value` or `enforcement` wrapper.

Directives: `registry` (registry URLs for the CLI and web console), `telemetry`
(OpenTelemetry export for ToolHive clients), `non_registry_servers` (whether the
CLI may create MCP servers outside the approved registry), `ca_certificate` (a
corporate CA for MCP server containers), `build_env` (environment variables for
MCP server containers), `gateway` (the AI Gateway URL the web console uses), and
`degraded_mode` (CLI behavior when Enterprise Manager is unreachable). Under the
umbrella chart, leave `registry.value.server_api_url` out: it defaults to the
Registry Server URL, and a set value that differs fails the render. Set
`telemetry.value.sampling_rate` explicitly; omitted, it resolves to zero on
clients.

Helm passes this object through without validating its fields. Enterprise
Manager validates field names, types, enforcement values, and degraded-mode
policy and duration at startup. Changes to this object trigger a rollout to load
the configuration. All callers receive the organization-wide values; the
`targets` field is accepted but is not evaluated. Store only non-sensitive
values here: the entire object is in a ConfigMap.

### `appConfig`

**Type:** `object`

**Default:** `{}`

Enterprise Manager's runtime configuration, for settings this chart has no
dedicated value for. The object is deep-merged over the configuration the chart
builds from the other values; keys set here win. The result is stored in a
ConfigMap, and a change rolls the pods. Never put secrets here: the chart
refuses database passwords, which come from the `existingSecret` values.

For example, `budgets.disconnectLimit` caps the cancelled streams one user or
service account may produce per period. `mode` is `observe` (the default), which
logs and counts the would-be refusals, or `enforce`, which refuses with `429` at
`max`. `period` is `day`, `week` (from Monday), `month` (the default) or `year`,
in UTC. `max` defaults to `500`, and `0` fails startup. `retentionPeriods`
defaults to `3`.

PostgreSQL port. `0` uses `global.postgres.port`, otherwise `5432`.

### `database.name`

**Type:** `string`

**Default:** `""`

Name of the Enterprise Manager database. Does not fall back to
`global.postgres`.

### `database.user`

**Type:** `string`

**Default:** `""`

Application database role. Must be a non-superuser without `BYPASSRLS`, distinct
from `migration.user`; otherwise row-level security is silently void and users
can read each other's data.

### `database.sslMode`

**Type:** `string`

**Default:** `""`

PostgreSQL SSL mode. Falls back to `global.postgres.sslMode`.

### `database.caBundleRef`

**Type:** `object`

**Default:** `{}`

CA bundle that verifies the Postgres server certificate, for a server signed by
a private CA (a corporate CA, AWS RDS). Falls back to
`global.postgres.caBundleRef`. Exactly one of `secretRef: {name: ...}` or
`configMapRef: {name: ...}`, plus `key` beside it (default `ca.crt`). Mounted
under `/etc/enterprise-manager/postgres-ca` and named by `PGSSLROOTCERT`; use
`sslMode` `verify-full` to check the host name too. Restart the pods after
rotating the bundle's contents in place.

### `database.maxConns`

**Type:** `int`

**Default:** `0`

Per-pod ceiling on the shared app connection pool. `0` allows one per CPU of
`resources.limits.cpu`, rounded up, at least 4 and at most 16. With no CPU limit
it counts the node's CPUs instead, so it is 16 on a node with 16 or more. The
maintenance and admin pools add up to 2 each. A rolling update runs 25% more
pods (rounded up, so at least one), so keep
`(replicas + surge pods) x (maxConns + 4)` under the server's `max_connections`.

### `database.existingSecret`

**Type:** `string`

**Default:** `""`

`global.postgres.existingSecret`.

### `database.existingSecretKey`

**Type:** `string`

**Default:** `"postgres-password"`

Key within `existingSecret` holding the app role's password.

### `database.dynamicAuth`

### `budgets.classifier`

**Type:** `object`

<details>

Conversation classifier, which labels captured conversations by calling this

### `budgets.classifier.baseURL`

**Type:** `string`

**Default:** `""`

Base URL of this platform's AI Gateway, including the version segment, such as

### `budgets.classifier.model`

**Type:** `string`

**Default:** `""`

**Type:** `int`

**Default:** `0`

Input token budget for `model`. Set it when the gateway's catalog has no context

**Type:** `string`

Pre-created Secret holding the classifier's full virtual key (`slk_...`).

### `budgets.classifier.existingSecretKey`

**Type:** `string`

**Default:** `"classifier-api-key"`

Key within `existingSecret` holding the virtual key.

**Type:** `object`

**Default:** `{"key":"ca.crt","secretName":""}`

**Type:** `string`

**Default:** `""`

Name of an existing Secret holding the issuing CA in PEM form.

### `budgets.classifier.caBundle.key`

**Type:** `string`

Key within `secretName` holding the CA.

### `budgets.classifier.allowInsecureTLS`

**Type:** `bool`

**Default:** `false`

Skip TLS verification of `baseURL`. Development and testing only: the classifier

### `budgets.classifier.instruction`

**Type:** `string`

**Default:** `""`

Instruction every classifier prompt starts with. The conversation is appended
below it and is untrusted, so state that it is data to classify and never
instructions. The chart's default values (`helm show values`) include an
example.

### `budgets.classifier.taxonomy`

**Type:** `list`

**Default:** `[]`

Free-form list of facets, each with a closed set of labels. Each entry has a
`facet` name and a `labels` list whose items carry a `name` and a `gloss` that
tells the model when the label applies. Every facet must include an `unknown`
label. An invalid taxonomy refuses startup even while the classifier is
disabled.

### `insights`

**Type:** `object`

**Default:** `{"freezeDeadline":""}`

Insights settings: how the labelled spend history is kept. A UTC day is frozen
into the cold history once its spend is rebuilt and every conversation in it has
a final label, or at the deadline below, so history outlives the event retention
without waiting on a classifier that is down.

### `insights.freezeDeadline`

**Type:** `string`

**Default:** `""`

How long after a UTC day closes it is frozen whatever its classification state,
as a Go duration. Empty applies the default, `72h`. A value above `168h`, or
above the spend retention (`appConfig.budgets.retentionWeeks`, 4 weeks by
default) minus three days, is reduced to that limit with a warning at startup.

### `directory.connectorVerification`

**Type:** `object`

**Default:** `{"enabled":true}`

Connector verification: before marking a go-live Connector write available,
Enterprise Manager dials the Connector's endpoint over TCP. `enabled` (default
`true`) turns verification on; it requires egress and DNS from the Enterprise
Manager pod to every Connector endpoint. Disabling it also removes the dial-time
private-address deny-list for Connectors with `allowPrivateIps`, and does not
re-evaluate Connectors already marked failed. Two optional keys are not set by
default: `dialTimeout`, a Go duration (empty uses `5s`), and
`allowedPrivateRanges`, a list of private CIDRs the verification dial may reach.
Every address in `allowedPrivateRanges` becomes probeable by any Admin, so keep
ranges narrow. Never add loopback; link-local and metadata ranges refuse
startup.

### `directory.issuers`

**Type:** `list`

**Default:** `[]`

SCIM issuers, one per IdP. Validated at startup; a malformed entry stops the
startup. Changes roll the Deployment. Each entry sets `id` (a URL-safe path
segment, `[a-zA-Z0-9._-]+`), `issuer_url` (the OIDC discovery base URL, HTTPS
only), `audience` (the expected `aud` claim in admin tokens), `binding_claim`
(the JWT claim carrying the stable user ID), `provisioning_attribute` (the SCIM
attribute written at provisioning time, default `externalId`),
`scim_bearer_token_ref` (the `namespace`, `name` and `key` of a Kubernetes
Secret holding the SCIM static bearer token), and optionally `group_variables`
(SCIM user attributes to create UserGroups from, each a bare attribute path or a
`path` with a `label`). A Microsoft Entra ID v2.0 issuer
(`login.microsoftonline.com`, `.us` or `login.partner.microsoftonline.cn`) must
set `binding_claim: oid`. Any other value, `OID` included, fails the render and
the directory's startup. In Entra, map `objectId` to `externalId` in the app's
SCIM attribute mappings, or every user provisioned with `binding_claim: oid` is
refused. `group_variables` creates one UserGroup per distinct (case-insensitive)
value. There is no cardinality cap, and groups of a removed variable are deleted
90 days later along with their budgets and grants.

### `directory.oktaReconcilers`

**Type:** `list`

**Default:** `[]`

Outbound Okta reconcilers, one per issuer, replacing inbound SCIM. The issuer
must omit `scim_bearer_token_ref` and use `binding_claim: uid` with the default
`provisioning_attribute`. Okta needs a `private_key_jwt` service app
(`okta.apps.read`, `okta.groups.read`, `okta.schemas.read`, `okta.users.read`)
and a custom admin role covering the app and selected groups.

Each entry sets `enabled`, `issuerID` (the issuer's `id`), `orgURL` (the Okta
org origin, HTTPS with no path, which may differ from the issuer URL), `appID`
(the application whose assigned users are the full population), `clientID`, and
`privateKeySecretRef` (the `namespace` and `name` of a Secret, with
`privateKeyKey` and `keyIDKey` naming the keys that hold the private key and its
key ID). Optional fields: `interval` (default `15m`, minimum `1m`),
`maxDeactivationRatio` (the largest fraction of active users one cycle may
deactivate; defaults to `0.10`, and `1` disables the check),
`allowEmptyPopulation` (allow an empty population while active users exist),
`logRawOktaAPIData` (debugging only: logs identity and profile data for the
whole population), and `selectedGroups` (Okta groups to project, by `id` or
exact `name`, with an optional `expectedName` that fails the cycle if the group
was renamed).

### `directory.kubernetesSecretRefs`

**Type:** `object`

**Default:** `{"allowed":[]}`

Kubernetes Secrets a Connector or identity provider credential may reference.
Each entry admits a namespace, optionally limited to `names`. Set entries under
`allowed`, each with a `namespace` and an optional `names` list. Requires
`directory.kek.enabled`, and the release namespace is refused. Each namespace
must exist before install.

⚠️ Every Platform Admin can read any allowlisted Secret, so use whole-namespace
entries only for dedicated namespaces.

### `directory.hmac`

**Type:** `object`

**Default:** `{"existingSecret":"","existingSecretKey":"hmac-key"}`

HMAC key used to hash virtual API keys. With `existingSecret` empty, Enterprise
Manager creates the Secret `<release>-directory-hmac` itself. To bring your own,
set `existingSecret` to a Secret whose `existingSecretKey` holds a key of at
least 32 bytes.

⚠️ Switching between a generated and your own Secret, or changing
`existingSecret`, after keys are issued invalidates every existing virtual key.
