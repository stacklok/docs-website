Run Virtual MCP Server (vMCP) on your workstation to expose a ToolHive group's
servers through one endpoint. This guide uses Fetch and OSV, which require no
API credentials. For an operator-managed deployment, use the
[Kubernetes quickstart](./quickstart.mdx).

## Prerequisites

- The [ToolHive CLI](../guides-cli/install.mdx) installed. Check with
  `thv version`.
- A running container runtime supported by ToolHive, such as Docker, Podman, or
  OrbStack.
- Visual Studio Code with GitHub Copilot for the client verification step. Other
  clients can use the endpoint according to their
  [connection requirements](../reference/client-compatibility.mdx).
- Port `4483` available on your workstation.

## Prepare a group

Create a group and start two servers in it. The explicit workload names keep
these examples separate from servers you already run:

```bash
thv group create vmcp-demo
thv run --group vmcp-demo --name vmcp-fetch fetch
thv run --group vmcp-demo --name vmcp-osv osv
thv list --group vmcp-demo
```

Wait until both workloads have status `running` before continuing. If you
already have a group to aggregate, substitute its group and workload names in
the following commands.

## Quick mode

Start vMCP from the group:

```bash
thv vmcp serve --group vmcp-demo
```

Keep this command running in its terminal while you complete the next steps. The
endpoint is `http://127.0.0.1:4483/mcp`. Quick mode prefixes tool names with
their workload name, so the Fetch tool is exposed as `vmcp-fetch_fetch`.

Quick mode uses anonymous authentication and accepts only loopback bind
addresses. To configure client authentication or bind to another interface, use
[config-file mode](#config-file-mode).

## Verify the tools

In another terminal, list the tools through vMCP:

```bash
thv mcp list tools --server http://127.0.0.1:4483/mcp
```

Check that the list includes tools prefixed with both `vmcp-fetch_` and
`vmcp-osv_`. Call the Fetch tool through the same endpoint:

```bash
thv mcp call vmcp-fetch_fetch \
  --server http://127.0.0.1:4483/mcp \
  --args '{"url":"https://example.com"}'
```

The result should contain the page text about use in documentation examples.
This verifies tool routing and a backend call, in addition to vMCP accepting
connections.

## Connect your client

Add the aggregated endpoint as a ToolHive-managed remote connection:

```bash
thv run http://127.0.0.1:4483/mcp --name vmcp-connection
thv client register vscode
```

ToolHive adds the connection to Visual Studio Code's configuration. If VS Code
is already registered, you can skip the registration command. Keep vMCP running
and reload VS Code if it hasn't picked up the connection.

In GitHub Copilot Chat, select **Agent** mode and enable the tools from
`vmcp-connection`. Ask it to use `vmcp-fetch_fetch` to retrieve
`https://example.com`. Approve the tool call when prompted, then check that
Copilot reports the page content and shows a tool invocation through the
aggregated connection.

For client registration details, see
[Client configuration](../guides-cli/client-configuration.mdx).

## Config-file mode

Use a configuration file when you want to save and customize the setup. Stop the
quick-mode process with **Ctrl+C** before starting another vMCP process on the
same port.

### Step 1: Generate a starter config

```bash
thv vmcp init --group vmcp-demo --output vmcp.yaml
```

The file contains the running backends' URLs and transport settings, plus
comments describing the main configuration sections. Regenerate it if you
recreate a backend and its address changes.

This is a local runtime configuration file. Kubernetes uses a
[`VirtualMCPServer` resource](./configuration.mdx) with a different structure.

### Step 2: Review and edit

For example, add the following `tools` list under the generated `aggregation`
section to limit OSV to looking up a vulnerability by ID. The Fetch backend
keeps its existing tool list:

```yaml title="vmcp.yaml aggregation section"
aggregation:
  conflictResolution: prefix
  conflictResolutionConfig:
    prefixFormat: '{workload}_'
  tools:
    - workload: vmcp-osv
      filter:
        - get_vulnerability
```

[Tool aggregation](./tool-aggregation.mdx) covers filtering, renaming, and
visibility rules. Keep the generated backend entries when editing the file.

### Step 3: Validate the config

```bash
thv vmcp validate --config vmcp.yaml
```

The command exits successfully when the configuration passes validation and
reports errors for invalid settings. It doesn't establish that the backends are
reachable; verify calls after starting the server.

### Step 4: Start the server

```bash
thv vmcp serve --config vmcp.yaml
```

Keep it running, then repeat [tool verification](#verify-the-tools) and use the
existing client connection. With the filter above, the tool list contains
`vmcp-fetch_fetch` and `vmcp-osv_get_vulnerability`.

When `--config` and `--group` are both set, `--config` takes precedence.

## Optimizer tiers

To search a large tool list instead of exposing every definition, stop the
running vMCP process and enable keyword search in quick mode:

```bash
thv vmcp serve --group vmcp-demo --optimizer
```

The endpoint exposes `find_tool` and `call_tool`. For keyword search, managed
embeddings with `--optimizer-embedding`, or an external embedding service, see
[Local optimizer setup](./optimizer.mdx#local-mode-cli).

## Enable audit logging

Add `--enable-audit` when starting vMCP to enable audit logging with defaults
when the loaded configuration doesn't already define an audit section:

```bash
thv vmcp serve --group vmcp-demo --enable-audit
```

Stop the current vMCP process before starting this one. See
[Audit logging](./audit-logging.mdx) for configuration options.

## Clean up

Remove the remote connection you added to your clients:

```bash
thv rm vmcp-connection
```

Stop the foreground vMCP process with **Ctrl+C**. If you created the example
group and backends in this guide, remove them:

```bash
thv rm vmcp-fetch vmcp-osv
thv group rm vmcp-demo
```

Delete `vmcp.yaml` if you generated it and no longer need it. Existing groups
and servers you used in place of the examples can stay running.
