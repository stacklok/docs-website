# Refresh generated references

Generated references are release artifacts checked into this repository. Correct
their upstream inputs or generation configuration, then regenerate the outputs.
Hand edits to generated pages are overwritten by the next release refresh.

## Inputs and generators

| Output                                                                               | Input and refresh mechanism                                                                                     |
| ------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------- |
| `docs/toolhive/reference/cli/*.md`                                                   | ToolHive's `thv-cli-docs.tar.gz` release asset, extracted by `sync-assets.mjs`                                  |
| API specifications in `static/api-specs/`                                            | Declared release assets or files from a release checkout, copied by `sync-assets.mjs`                           |
| Registry JSON schemas in `static/api-specs/`                                         | ToolHive release assets; `bundle-upstream-schema.mjs` resolves the upstream registry schema's remote references |
| CRD schema directories in `static/api-specs/`                                        | YAML from a declared release asset or source directory, processed by `extract-crd-schemas.mjs`                  |
| CRD pages under `docs/toolhive/reference/crds/` and `docs/platform/reference/crds/`  | Extracted schemas, processed by `generate-crd-pages.mjs`                                                        |
| `src/components/CRDReference/all-schemas.ts`                                         | Consolidated schema barrel generated by `generate-crd-barrel.mjs`                                               |
| Helm pages under `docs/toolhive/reference/helm/` and `docs/platform/reference/helm/` | Released chart values and comments, processed by `generate-helm-reference.mjs` with `helm-docs`                 |

The release workflow coordinates these steps through
[`sync-assets.mjs`](../../scripts/upstream-release/sync-assets.mjs),
[`extract-crds.mjs`](../../scripts/upstream-release/extract-crds.mjs), and
[`generate-helm-reference.mjs`](../../scripts/upstream-release/generate-helm-reference.mjs).
Each script reads declarations from
[`upstream-projects.yaml`](../../.github/upstream-projects.yaml). Projects without
the relevant declarations skip that generation step.

CRD set declarations also drive the remark plugin and sidebar configuration
through [`crd-sets.mjs`](../../scripts/lib/crd-sets.mjs). The extraction driver
regenerates the consolidated schema barrel after processing the project's sets.

Helm generation uses the
[`helm-values.gotmpl` template](../../scripts/upstream-release/helm-values.gotmpl)
and `helm-docs` 1.14.2, pinned and checksum-verified in the release workflow.
`helm-docs` is a generation dependency; the website builds from checked-in MDX.

## Choose where to make a correction

- **CLI descriptions, commands, and visibility:** change the upstream ToolHive
  CLI source. The next released CLI documentation asset supplies the correction.
- **API fields, operations, and descriptions:** change the upstream API source
  or specification generation. Keep the copied specifications intact here.
- **CRD fields, defaults, and descriptions:** change the upstream CRD source.
  For page introductions maintained here, edit
  [`crd-intros.mjs`](../../scripts/lib/crd-intros.mjs). Landing-page text belongs
  in the project's `crds` declaration.
- **Helm defaults and field descriptions:** change the upstream chart values
  and comments. Page introductions, related links, and curated descriptions for
  passthrough blocks belong in the project's `helm` declaration.
- **Output formatting or rendering:** inspect the corresponding generator or
  shared component. Regenerate artifacts when changing generation behavior.

If generated content must be removed before an upstream release supplies the
change, flag it to a maintainer to coordinate the upstream fix and publication.

## Validate a refresh

1. Confirm the release tag and declared inputs. Keep API, CLI, CRD, and Helm
   outputs aligned with the release being documented.
2. Inspect the generation diff for unexpected deletions, missing fields,
   unresolved references, and changes outside the declared output directories.
3. When changing Helm generation, run its tests:

   ```bash
   node --test scripts/upstream-release/generate-helm-reference.test.mjs
   ```

4. Run formatting, lint, and the production build:

   ```bash
   npm run prettier
   npm run eslint
   npm run build
   ```

5. Review representative API, CRD, and Helm pages in the preview. Check headings,
   field tables, defaults, links, and section anchors. After publishing rendering
   changes, validate the [search extractors](../search/README.md).

Generated files excluded from formatting or lint still require source and
rendering review. A successful generation step confirms that the scripts ran;
it does not establish that an upstream description or default is correct.
